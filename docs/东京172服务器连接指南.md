# 东京主服务器（172.81.98.55）连接方式指南

> 更新日期：2026-09-21
> 适用机器：172.81.98.55（东京 / 16核 / 15G / 449G / 优化线路，2026-09-12 起为唯一生产服务器）
> 旧主服务器 38.181.44.164（美国）现仅作 MySQL/Redis 备用与文件中转，见文末

---

## 一、SSH 直连（操作机 → 172）

```bash
ssh root@172.81.98.55
```

- **免密**：操作机（本 Windows 工作机）使用 `C:\Users\a1033\.ssh\id_rsa`，公钥已装服务器 `authorized_keys`
- 无需指定 `-i`，默认密钥即命中；如需显式指定：

  ```bash
  ssh -i ~/.ssh/id_rsa root@172.81.98.55
  ```

- SSH 仅密钥认证（密码登录未启用）
- 常用运维命令参考《docs/172推流服务器运维说明.md》（systemctl / SRS / worker 等）

## 二、没有宝塔面板

⚠️ **172 上没有安装宝塔/aaPanel**（`bt` 命令不存在，无面板端口）。

- 一切运维走 SSH + 命令行
- nginx 配置：`/etc/nginx/`（sites-enabled 4 站 + `conf.d/00-cn-block.conf` CN 屏蔽 + `bunny_realip.conf`）
- 不要按旧文档找 164 的宝塔地址（`38.181.44.164:10896/b8555de2` 是 164 的，且已停用业务）

## 三、代码部署（不要手动改线上文件）

**唯一正规部署方式** —— 一条命令从 gitee 拉取构建：

```bash
ssh root@172.81.98.55 /root/deploy/deploy_web.sh [all|vue|php|admin|static|worker]
```

| 动作 | 内容 |
|---|---|
| `static` | rsync `ai-girl-malaysia.com/` + `ai_web/` 静态站 |
| `php` | rsync php 后端（自动处理 vendor/runtime，不 --delete） |
| `vue` / `admin` | 目标机 npm 构建 vue/dist 与 admin/dist |
| `worker` | 更新 worker.py 并重启 11 路推流 |
| `all` | 以上全部 |

**已知坑（2026-09 多次踩过）**：

1. **部署副本必须先对齐 gitee 再跑脚本**，否则旧副本会覆盖线上新文件（Home.html 短剧栏曾被这样覆盖过一次）：

   ```bash
   ssh root@172.81.98.55 "cd /root/deploy/zhibo && git fetch origin && git reset --hard origin/main"
   ssh root@172.81.98.55 /root/deploy/deploy_web.sh static
   ```

2. 172 上副本的 gitee remote 名是 **`origin`**（不是 `gitee`），deploy key 在 `/root/.ssh/gitee_deploy`（已配好，无需手动指定）
3. 静态站目录 rsync 是 `--delete` 全量镜像，**以 gitee 为准** —— 改动必须 commit + push gitee 后再部署，直接 scp 热修的文件会在下次部署时被冲掉

## 四、文件传输

### 小文件（配置/单页面，<10MB）

```bash
scp 本地文件 root@172.81.98.55:/目标路径/
```

### 大文件（家宽直传极慢，走 164 中转）

操作机 → 172 直连实测仅 **90~250 KB/s**（跨境家宽上行瓶颈），1GB 级文件必须中转：

```bash
# ① 操作机 → 164（可 6 路分卷并行提速，~500KB/s）
split -b 100M -d -a 3 大文件.tgz part_
scp -i ~/.ssh/douyin_38_181 part_* root@38.181.44.164:/tmp/parts/   # 分批后台传
ssh -i ~/.ssh/douyin_38_181 root@38.181.44.164 "cat /tmp/parts/part_* > /tmp/大文件.tgz && md5sum /tmp/大文件.tgz"

# ② 164 → 172（机房互联 ~2.7MB/s+）
ssh -i ~/.ssh/douyin_38_181 root@38.181.44.164 "scp /tmp/大文件.tgz root@172.81.98.55:/tmp/"

# ③ 172 上校验 md5 后解压
```

- 三端 MD5 必须一致再解压
- 传完清理各端 /tmp（164 与 172 磁盘都不大）

## 五、数据库 / Redis（都在 172 本机）

```bash
# MySQL（应用库 zhibo）
mysql -uzhibo -p12345678 zhibo

# Redis（礼物队列等）
redis-cli -a redis4live2026
```

- MySQL 仅监听 127.0.0.1；AI 电脑等外部机器连库走公网 3306 时账号同 zhibo/12345678
- 配置来源：`/www/wwwroot/douyin/php/.env`

## 六、AI 电脑 → 172

- **SSH 免密不通**（`ai_tunnel_key` 登 172 被拒，Permission denied）—— AI 电脑目前无法直接 ssh/scp 到 172，大文件传输以操作机为中转
- AI 电脑访问 sugus.ai API 走 **tinyproxy 代理**（172:3128）：

  ```
  http://llmproxy:<密码>@172.81.98.55:3128     # 密码见 AI 电脑 D:\custom_video\worker_v50.py 的 PROXY 配置
  ```

- AI 电脑 SSH 登录方式（操作机 → AI 电脑）见《AI电脑远程连接操作说明.md》

## 七、域名 / CDN / 屏蔽

```
用户 → www.sugus.ai (Bunny CDN, ever-candy.b-cdn.net) → 回源 172
        ├── 80   主站（/ai/ = ai-girl-malaysia.com 静态站，/api/ 反代 php，CN 屏蔽 403）
        ├── 8082 Bunny 回源口（root 直指静态站目录 + /storage/，mp4 缓存 1d）
        ├── 8081 sugus.it.com 管理后台（CN 屏蔽豁免，运营国内可访问）
        └── 1935 SRS RTMP（Docker，--network host）
```

- 验证 CDN 链路要从海外出口 curl（在 172 上 `curl https://www.sugus.ai/...` 即可）；国内直连 403 是设计行为
- html/js/css 不缓存（改完即时生效），mp4/图片缓存 1d（Bunny 侧可能另有缓存，更新素材建议换文件名）
