# 漂移检测与防漂移工具（2026-11-10）

## 这套工具解决什么问题

2026-11-10 发现：同事的 `shell-new.js` 语言修复只存在于 3 台服务器，gitee 里没有
（服务器 `lang1` / 上游 `uinfo1`）。**下一次 `sync_clients.py` 就会把它覆盖掉。**

为什么之前发现不了：

1. 客户服务器 `/www/wwwroot/douyin` **不是 git 仓库** —— 没有 `git status` 可看
2. `sync_clients.py` 只管「往服务器推」，不管「服务器有没有被人改过」
3. 手工 `md5sum` 比对极其繁琐，还要手工排除 `apply_brand` 的品牌差异

## 一、漂移检测：`check_drift.py`

```bash
python .zcode/check_drift.py                  # 全部站点
python .zcode/check_drift.py --client heygirl # 单站
python .zcode/check_drift.py --diff heygirl   # 附具体差异
python .zcode/check_drift.py --all            # 扫全部文件（默认只扫核心目录）
python .zcode/check_drift.py --quiet          # 只看汇总
```

**只读，不改服务器任何文件。** 有漂移时退出码为 1，可以挂到 cron 里告警。

### 判定口径

以 `gitee/main` 为「应然状态」，逐文件比对。比对前两侧都做**归一化**：

| 归一化 | 目的 |
|---|---|
| 行尾 `\r\n` → `\n` | Windows 仓库 vs Linux 服务器 |
| 品牌词 `sugus/heygirl/kelymi/kiss/kisss` → `<B>` | `apply_brand` 会替换品牌名 |
| 域名后缀 `.ai/.live/.autos/...` → `.<TLD>` | 各站域名不同 |
| CDN 地址 `https://xxx.b-cdn.net` → `<CDN>` | 各站 CDN 不同 |
| 资源引用 `<CDN>/ai/assets/x` 与 `./assets/x` → `<A>/assets/x` | 同一文件的两种写法 |
| 品牌邮箱 `support@xxxmail.ai` → `<MAIL>` | apply_brand 替换 |
| `?v=xxx` → `?v=X`（第二遍判定用） | 版本号差异是发版常态 |

### 结果分类

| 分类 | 含义 | 要不要处理 |
|---|---|---|
| **一致** | 归一化后完全相同 | — |
| **仅版本号** | 只有 `?v=` 不同 | 通常不用管 |
| **内容漂移** | 逻辑不同 | ⚠️ 要查：谁改的、要不要搬回仓库 |
| **缺失** | 服务器没有这个文件 | 通常正常（客户站没部署该功能） |
| **版本号异常** | HTML 引用了上游没有的 `?v=` | ⚠️ 典型的「服务器手改没进仓库」信号 |

### HTML 为什么不逐字节比

`apply_brand` 会改 favicon 文件名、域名、品牌名，**每个 HTML 都有差异**，
逐字节比全是噪音。所以 HTML 单独做「版本号体检」：只抓
`src="./js/xxx.js?v=xxx"` 的引用版本，和上游同页面对比，
**只报「服务器引用了上游没有的版本」** —— 这正是 2026-11-10 那次的信号。

## 二、同步工具的三处改造

### 1. 同尺寸漏推（`sync_clients.py` upload）

**旧逻辑**：远端文件大小相同 → 判定「已就位」跳过。
**问题**：2026-11-10 给 `chat.js` 补一个分号，文件大小**恰好不变**（160134 字节），
被跳过，线上一直跑着没修复的版本，排查半天。

**新逻辑**：大小相同还要比 md5（`_md5_remote` 优先跑 `md5sum`，失败再 sftp 流式读）。

### 2. PHP 后端纳入同步（`in_scope()` + `upload(php_root=)`）

**旧逻辑**：`in_scope()` 只认站点目录，PHP 改动**必须手工 SFTP**。
这正是「改完服务器没进仓库」反复发生的根因之一 —— 工具没给正路。

**新逻辑**：
- `in_scope()` 加 `php/` 分支，只推 `.php/.json/.phtml` 和 `php/sql/*.sql`
- **永不推** `.env`、`php/vendor/`、`php/runtime/`、`php/storage/`
- 上传时 `php/xxx` 落到 `{site 上一级}/php/xxx`
- 推完 PHP 自动 `systemctl reload php-fpm`（opcache 会缓存，不 reload 等于没生效）
- 经跳板（sugus）时同样支持：php 文件先到跳板 `/tmp/sync_<name>_php`，再 tar 到远端 php 根

### 3. `connect()` 支持非标准 SSH 端口

kiss 新机是 `20203` 端口。`connect()` 现在读 `cfg["port"]`（默认 22）。

## 三、推荐工作流

```bash
# 改代码前：先看有没有人绕过仓库改过服务器
python .zcode/check_drift.py

# 如果报漂移：先把改动搬回仓库
#   1) 拉服务器文件对照（--diff 看具体差异）
#   2) 改本地仓库 → commit → push
#   3) 跑 sync_clients.py 覆盖服务器（此时两边一致）

# 正常发版
git add -A && git commit -m "..." && git push gitee main
python .zcode/sync_clients.py --client heygirl --dry-run
python .zcode/sync_clients.py
```

## 四、已知限制

1. **`apply_brand` 的差异性归一化不可能 100% 全覆盖**。如果某次报「漂移」但
   `--diff` 看只是品牌相关，说明归一化规则还差一条，补 `check_drift.py` 顶部的
   `*_RE` 与 `.zcode/remote_norm_md5.py` 里对应的正则（**两边必须同步改**）。
2. **「缺失」不算漂移**。客户站可能没部署上游某些模块（如 heygirl 缺
   `HissPayService.php`），这是正常的。
3. **默认只扫核心目录**（`js/`、`php/app/live/service/`、`php/app/api/controller/`、
   `php/config/`）。扫全量（`--all`，680 文件）会更慢，但仍在可接受范围。
4. **不检测数据库结构差异**。SQL 迁移脚本有改动会报在 `php/sql/` 里，
   但「服务器上到底跑没跑过这个 SQL」无法从文件比对得出。
