## 一、隔离保证（这是本方案的第一原则）

新通道与现有通道在**每一层**都分开，互不感知：

| 维度 | 现有通道（不动） | 新通道 |
|---|---|---|
| 数据库表 | `lp_ai_task` 里 `task_type=custom_video` | 同表，`task_type=ai_short_video` |
| 队列查询 | `pending` 只查 `IN('custom_video','custom_image')` | 新接口只查 `='ai_short_video'` |
| API 命名空间 | `/api/customVideo/*` | `/api/aiShort/*` |
| worker 进程 | `worker_gpu.py` ×4（`custom-video-worker@`） | `worker_short.py` ×1~4（`custom-short-worker@`） |
| worker 目录 | `/opt/cv/<site>/` | `/opt/cv/short/<site>/` |
| 单例锁 | `/opt/cv/<site>/worker.lock` | `/opt/cv/short/<site>/worker.lock` |
| 工作流 JSON | `h3_fingering_api.json` 等 3 个 | `short_base.json`（独立副本） |
| 提示词来源 | `wf_prompts.json`（随机池） | `lp_short_preset.prompt`（**精确一条**） |
| 前端 | `Image.html` 现有卡片 | 暂不接（先 API 可用，前端二期） |

**关键点**：因为 `pending()` / `accept()` / `uploadVideo()` 都硬编码了
`IN('custom_video','custom_image')`，新 `task_type` 天然不会被老 worker 捞走，
老通道也不会看到新任务。**这是零改动的隔离，不是靠约定。**

## 二、数据模型

```sql
-- 迁移脚本：php/sql/upgrade_ai_short.sql
CREATE TABLE IF NOT EXISTS `lp_short_preset` (
  `id`           BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `code`         VARCHAR(32)  NOT NULL DEFAULT '' COMMENT 'API 寻址键 gs-01..gs-50',
  `title`        VARCHAR(120) NOT NULL DEFAULT '' COMMENT '标题',
  `prompt`       TEXT         NOT NULL COMMENT '该条专属提示词（英文）',
  `category`     VARCHAR(32)  NOT NULL DEFAULT '' COMMENT 'blowjob/cowgirl/doggy/other/cumshot/solo',
  `kind`         VARCHAR(16)  NOT NULL DEFAULT 'video' COMMENT 'video|image（gs-08 是图片）',
  `lora_chain`   JSON         NULL COMMENT '[[文件名,强度],...]；空=仅 motion_enhancer',
  `duration_sec` TINYINT UNSIGNED NOT NULL DEFAULT 8 COMMENT '生成时长(秒)',
  `cover_url`    VARCHAR(500) NOT NULL DEFAULT '' COMMENT '封面 /ai/media/gs/xx.jpg',
  `preview_url`  VARCHAR(500) NOT NULL DEFAULT '' COMMENT '参考视频 /ai/media/gs/xx.mp4',
  `weigh`        INT NOT NULL DEFAULT 0,
  `status`       TINYINT NOT NULL DEFAULT 1 COMMENT '1启用 0下架',
  `created_at`   DATETIME DEFAULT NULL,
  `updated_at`   DATETIME DEFAULT NULL,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_code` (`code`),
  KEY `idx_status_weigh` (`status`, `weigh`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='50条短视频预设（独立通道）';
```

**任务表不新增字段**。`lp_ai_task.content` 是 `varchar(1000)`，装不下长 prompt + lora_chain，
所以 content **只存引用，不存正文**：

```json
{"preset_code":"gs-17","image_url":"https://...","duration_sec":8,
 "paid_tokens":0,"retry":0}
```

真身（prompt / lora_chain）在 `lp_short_preset`，由服务端在 `/pending` 响应里 join 下发。
好处：① 绕开 varchar(1000) 限制；② 提示词只有一处真相；③ `lp_ai_task` 里不落敏感文案。

## 三、API 契约

命名空间 `/api/aiShort`，与 `/api/customVideo` 完全平行。

### 3.1 预设列表（公开）

```
GET /api/aiShort/presets
→ { "code":"00000", "data":{ "list":[
      { "code":"gs-01", "title":"Deepthroat (POV) - 8s", "category":"blowjob",
        "kind":"video", "duration_sec":8,
        "cover_url":"/ai/media/gs/01.jpg", "preview_url":"/ai/media/gs/01.mp4" }
      , ... 共 50 条 ] } }
```

**不返回 prompt / lora_chain**（防止提示词被直接抓走）。

### 3.2 单条详情（需登录）

```
GET /api/aiShort/preset?code=gs-17
→ { "data":{ "code":"gs-17", "title":"...", "prompt":"...",
             "lora_chain":[...], "duration_sec":8, "kind":"video", ... } }
```

### 3.3 提交生成（需登录）

```
POST /api/aiShort/submit          multipart
  image         必填   jpg/png/webp ≤10MB
  preset_code   必填   如 gs-17
  agreed_policy 必填   1
  duration_sec  可选   覆盖预设默认值（上限 15）
→ { "data":{ "task_id":123, "task_no":"AS...", "status":"pending",
             "remain":5, "balance":120 } }
```

额度/扣费口径**与 customVideo 一致**（复用 `GenCreditService` + `WalletService`），
避免两套规则打架。失败同样走退款。

### 3.4 我的作品（需登录）

```
GET /api/aiShort/myList?page=1
→ 列表含 task_no / title / status / video_url / cover_url / duration
```

### 3.5 worker 侧接口（X-Api-Key 鉴权）

```
GET  /api/aiShort/pending?count=1     → 含 preset_code + prompt + lora_chain + duration_sec
POST /api/aiShort/accept              task_id
POST /api/aiShort/upload              task_id + video + cover
POST /api/aiShort/complete            task_id + duration
GET  /api/aiShort/stats
```

### 3.6 对外调用示例

```bash
# 1) 登录拿 token（沿用现有登录）
TOKEN=$(curl -s -X POST https://sugus.ai/api/live/login \
  -d 'account=xxx&password=yyy' | jq -r .data.token)

# 2) 看有哪些预设
curl -s https://sugus.ai/api/aiShort/presets | jq '.data.list[] | {code,title}'

# 3) 指定第 17 条生成
curl -s -X POST https://sugus.ai/api/aiShort/submit \
  -H "Authorization: Bearer $TOKEN" \
  -F image=@her.jpg -F preset_code=gs-17 -F agreed_policy=1

# 4) 轮询结果
curl -s "https://sugus.ai/api/aiShort/myList" -H "Authorization: Bearer $TOKEN"
```

def build_wf(preset):

## 五、GPU 争用：这是本方案唯一的硬约束

实测数据（真机，本轮跑出）：

| 配置 | 时长 | 耗时 |
|---|---|---|
| 2 层 LoRA（现网现状） | 3s | 90.6s |
| 4 层 LoRA | 3s | 160.1s |
| 4 层 LoRA（重复跑，验缓存） | 3s | 140.6s ← 缓存仅省 12% |
| **4 层 LoRA** | **7s** | **611.6s（10.2 分钟）** |
| 6 层 LoRA | 3s | 220.1s |

一台卡、一条 ComfyUI 队列、现在 4 个 worker 已在抢。**再起一个通道，不会变快，只会排队更长。**

三个可选策略（需要你选）：

| 策略 | 做法 | 代价 |
|---|---|---|
| **A 软限流（推荐）** | 新 worker 每轮只取 1 条，且两次之间 sleep 可配（默认 60s） | 50 条跑完约 4-5 小时，但不饿死老通道 |
| **B 独立优先级** | 给 `ai_short_video` 用较低 `priority`，老通道先取 | 新通道在高峰期几乎不动 |
| **C 加卡/分时** | 夜间批量跑，或加第二张卡 | 成本 |

我建议 **A + B 组合**：默认软限流，同时 `priority` 低于老通道。

## 八、风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| **GPU 争用** | 一张卡、一条队列，老通道 4 个 worker 已在跑 | 新 worker 软限流 + 低 priority（第五节 A+B） |
| prompt 字段溢出 | `lp_ai_task.content` 是 varchar(1000) | content 只存 `preset_code`，正文在 preset 表 |
| 提示词泄漏 | `/presets` 若返回 prompt 等于公开 | 列表不返回，详情需登录，worker 接口需 key |
| 老通道被误改 | 共用 `worker_gpu.py` 会牵连四站 | **新文件 worker_short.py，不 import 老逻辑** |
| 四站 DB 漂移 | 每站独立 MySQL，建表要各跑一次 | 迁移脚本幂等（`IF NOT EXISTS`），部署清单逐站核对 |
| 黑图复发 | 历史事故（sage attention） | worker_short 复用 v6.1 的 `assert_not_black` / `assert_video_not_black` |
| 时长失控 | 素材原有 5-60s 不一 | `duration_sec` 默认 8，提交侧上限 15 |
| 11 条无 LoRA | 动作覆盖不全 | 先出片看效果，不达标再训练 |
