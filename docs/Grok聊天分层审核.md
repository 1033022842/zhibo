# Grok 聊天分层审核

## 已实现（本次）

- 新增 `php/app/live/service/ChatSafetyService.php`：`tier()` 用 `VipService::entitlements()` 的 `is_vip` 分 `paid` / `free` 两档；`systemRules()` 给出两档 system 规则（paid 只有红线，free 额外「暧昧但不露骨」）；`needsReview()` 用多语关键词粗筛，`allowsInput()` / `allowsReply()` 命中才追加一次小模型审核（`temperature=0`，8 token，返回 PASS/BLOCK）；`redirectReply()` 按档位与语言给角色口吻的转移话题文案。
- `Live::chat()` 接入：system 末尾追加档位规则（优先级压过风格设定与人设）；命中关键词先审输入，BLOCK 时直接用转移文案、不再调主模型；主模型返回后命中关键词再审输出，BLOCK 时替换为转移文案。被拦的一轮打 `refused=true`，**不计额度、不扣代币**。
- `iceBreaker()` 与送礼回复（`sendChatGift()`）的 system 也追加红线，避免从开场白或礼物分支绕开。
- 游客链路仍走 `GuestChatPolicy`（更严的 PG 口径），与登录档位互不影响。
- 单测：`_guest_chat_validation/safety_test.php`（仓库外临时脚本）覆盖分档、粗筛、规则拼接、多语转移文案与审核放行/拦截。

## 当前行为

- `php/app/api/controller/Live.php` 的 `chat()` 在接入新策略之前：服务端读取 VIP 权益但仅用于额度与计费，注册免费用户和付费用户使用同一套聊天人设提示，人设和用户自定义设置还拼入同一条 system 消息。
- 同一个 `chat()` 既处理文字，也处理通话转写后的回复；关键词媒体与特殊视频有独立分支。`iceBreaker()` 和 `sendChatGift()` 另外调用聊天模型。仅改一条 system prompt 无法覆盖这些出口。
- 本次游客分支只接受文字，角色由服务端公开目录确定，不接收客户端人设或历史；模型生成后先审核候选回复，再决定返回原文还是简短换话题。游客的开场白不请求模型。现有注册用户的提示、权益和计费没有在本次改动中重写。

## 建议规则

| 服务端档位 | 聊天口径 |
| --- | --- |
| 游客 | 轻松友好、非露骨。五条文字试聊，不开放语音、发图、送礼，不自动付费。 |
| 已注册、未付费或付费状态不明 | 可以聊天、轻度调情；不生成露骨性描写、性化角色扮演或主动引导去索取成人素材。 |
| 确认拥有付费权益 | 可以有较强的浪漫语气；以下共同红线不随付费解除。 |

共同红线：不参与对未成年或年龄不明确者的性化内容，不参与亲属或家庭角色（包括继亲、养亲、假扮亲属）的性化或恋爱角色扮演。普通的父母、女儿、家庭生活等话题照常聊天，不靠单词匹配一律封禁。碰到违规内容就简短转题，例如「我们换个话题吧。你最近有什么开心的事？」；不要羞辱用户，也不要展开复述。

## 接入点与验收

1. **权益以服务端为准。** `VipService::entitlements()` 适合识别有效会员，但不能证明用户曾充值：现有后台可手动设置 VIP，到期或纯充值用户也不等于免费用户。若产品口径是「曾付费」，用已结算的正额订单并排除已退款／冲正；若口径是「当前付费」，更适合新增明确的聊天内容权益。余额、赠送币和请求中的 `pay_tokens` 都不是付费凭据。
2. **同时看输入与输出。** 先用最新消息 + 有限最近历史识别上下文中的年龄、亲属角色与意图，违规直接返回固定文案，不发起生成，不触发素材和扣费。再审核候选回复；审核不可用时降级为固定中性回复或暂时重试，原文不下发、不朗读、不存为助手回复。人设、用户偏好和历史都作为数据，不覆盖统一规则。优先使用独立审核模型；当前游客实现的第二次 Grok 调用是初版，不等于独立分类器，也不保证识别所有变体。
3. **覆盖全部出口。** 同一策略用于文字、通话转写、开场白、礼物回复、关键词素材与特殊视频。收紧时沿用现有计费与权限判断，受限素材不能借回复分支绕过访问控制。
4. **先灰度，再全量。** 用非露骨测试样本覆盖普通家庭上下文、年龄不明、跨轮角色关系变化、切换语言、降级／超时和付费状态变更。指标看误杀率、漏拦率、P95 延迟、每轮额外调用和付费转化；日志只记录档位、原因分类、耗时，不记录对话原文。
