# 搭建第二套本项目 — 完整清单

> 适用：把这套 AI 直播平台（网站 + 直播 + AI 视频生成）完整复制到一台新服务器
> 依据：2026-09-23 在 38.247.166.124 的实际搭建全过程整理
> 定位：并行环境（不影响已有 172 生产与 AI 电脑）

---

## 一、服务器规格要求

| 项 | 最低 | 推荐（本次实测机型） | 说明 |
|---|---|---|---|
| 系统 | Ubuntu 22.04 | **Ubuntu 24.04 LTS** | 24.04 自带 PHP8.3/MySQL8/Redis7，最省事 |
| CPU | 8 核 | 16–32 核 | 网站+推流很轻；AI 生成靠 GPU 不靠 CPU |
| 内存 | 16 G | 32–82 G | ComfyUI 加载 20G 级模型时内存要够 |
| 磁盘 | 200 G | **≥ 400 G SSD** | 站点 3G + 素材 4G + 模型 71G + venv 17G + 余量 |
| GPU | 无（可跑网站+直播） | **NVIDIA 显存 ≥ 24G** | 跑 AI 视频生成必需；需支持 CUDA 12.8+ |
| 架构 | x86_64 | x86_64 | — |

> ⚠️ 若只要「网站 + 直播」不要 AI 生成：无 GPU 即可，磁盘 100G 够用。
> 若要 AI 生成：必须 N 卡，且驱动支持 CUDA 12.8（Blackwell/50 系需更新驱动）。

### 两种直播模式（二选一）

| 模式 | 适用 | 做法 |
|---|---|---|
| **A. 本机推流** | 服务器上行带宽充足 | 跑 `live-worker@{room}` → 本机 SRS → 本机 HLS 直出 |
| **B. 共用 CDN**（本次采用） | 上行小 / 跨境慢 | 不推流，直播 HLS 指向已有 CDN，在播状态从源机 SRS 同步 |

## 四、部署步骤

> 顺序原则：**先传数据（最长路径）→ 装环境 → 起服务 → 验证**

### 阶段 0：环境准备（~20 分钟）
```bash
apt-get update && apt-get install -y <见 2.5 清单>
systemctl enable --now php8.3-fpm mysql redis-server docker
```
- 建 MySQL 库与账号，改 root 密码（或建独立账号）
- 建目录：`/www/wwwroot/douyin`、`/data/media`、`/data/runtime`、`/data/hls`

### 阶段 1：搬文件（代码 + 素材）
```bash
# 从源机拉（若两机互通，走内网/机房互联，速度远快于家宽）
rsync -a --exclude 'runtime/' --exclude 'node_modules/' \
  源机:/www/wwwroot/douyin/php/ /www/wwwroot/douyin/php/
# 同样拉 vue/dist、admin/dist、ai-girl-malaysia.com、ai_web、apps/ws-webman
# 拉 /data/media、/data/runtime/ts_cache、php/public/storage
```
⚠️ **上传方向选最稳的路**：本次「操作机→新机」和「AI电脑→新机」的 TCP 都被跨境线路阻断，
最终走了 **AI电脑 → 172 → 新机** 两跳中转。搭第二套时先测通路再决定方案。

### 阶段 2：导数据库
```bash
mysql -uroot -p -e "CREATE DATABASE live_platform DEFAULT CHARSET utf8mb4 COLLATE utf8mb4_unicode_ci;"
mysql -uroot -p live_platform < zhibo_full.sql
# 迁移包可能漏文件，务必核对命令类齐全：
#   php/app/command/ 下应有 7 个 cron 命令（含 EthRechargeScanCron）
```

### 阶段 3：配置
1. **`php/.env`**：DB 指向本机；Redis；`[AI] HLS_CDN_DOMAIN`（模式 B 才填）
2. **nginx**：三个 server（80/8081/8082），注意：
   - `location = /` → 302 `/ai/Home.html`
   - `/api/` 与 `*.php` 走 php-fpm（PATH_INFO 模式）
   - `/admin/` 静态优先，回退 `@admin_api`
   - `/hls/` alias 到 HLS 目录
3. **admin 账号**：若 dump 里没有可登录账号，需手工建（见「五、必改项」）
4. **systemd**：`zhibo-ws.service`（webman）、`live-worker@.service`（或模式 B 不装）

### 阶段 4：起服务并验证
```bash
systemctl restart nginx php8.3-fpm mysql redis-server zhibo-ws
# 验证：见「七、验证清单」
```

### 阶段 5：AI 生成（仅 GPU 机）
```bash
# 1) venv + torch(cu128) + ComfyUI requirements
# 2) 部署 30 个 custom_nodes + 装各自 requirements
# 3) 迁 15 个模型 + extra_model_paths.yaml
# 4) 复制 /opt/custom_video（worker.py Linux版 + 工作流 + 提示词）
# 5) systemd: comfyui.service + custom-video-worker.service
```

## 五、必改项（照抄会踩的坑）

| # | 项 | 说明 |
|---|---|---|
| 1 | `php/app/api/controller/Whep.php` | 硬编码 `172.81.98.55:8889`，改成 `env('AI.MEDIAMTX_WHEP_BASE', 'http://127.0.0.1:8889')` |
| 2 | `SrsService.php` | 原只认 `getenv()`，需支持 `.env`（模式 B 要指向远端 SRS） |
| 3 | `config/console.php` | 命令注册表，注意别漏 `EthRechargeScanCron` |
| 4 | `php.ini` 上传限制 | 默认 2M 会导致视频回传 500 → 改 `30M/32M/memory 128M` |
| 5 | `php-fpm pool www.conf` | `clear_env = no` + `env[SRS_API_HOST]`（若用系统环境变量方式） |
| 6 | admin 账号 | BuildAdmin 用 bcrypt；`status` 必须是字符串 `enable`（不是 1）；用服务器端 `password_hash()` 生成，别让 shell 转义 `$2y$` |
| 7 | SRS `hls_path` 与 nginx `/hls/` | 两者必须指向同一目录（模式 A） |
| 8 | `/data/hls` 属主 | 归 www-data，否则 nginx 403 |

## 六、踩坑记录（实战）

1. **跨境 TCP 阻断**：ICMP 能通但 TCP 22/80 不通 → 换中转路径，不要死磕直连。
2. **`rsync --inplace` 会毁数据**：源文件不完整时会把目标已有完整文件截断 → 一律用默认（临时文件+原子替换）。
3. **传输竞态**：中转转发要等上传方写完再动 → 用「`.ok` 标记」协议，别靠"文件大小稳定"判断。
4. **文件名含空格/特殊字符**：`scp`/`ssh` 远程路径务必加引号，PowerShell 里尤其容易错。
5. **`git clone` 会重建目录**：ComfyUI 装到一半若重新 clone，会把已建好的 `models/` 子目录抹掉 → 先 clone 再建目录。
6. **ComfyUI 的 `user/` 目录属主**：必须是运行用户，否则 `PermissionError` 起不来。
7. **venv 属主**：pip 安装需要运行用户可写，`root` 装的 venv 要 `chown`。
8. **TensorRT 版本**：RIFE 节点按 CUDA 版本自动装，cu13 包与 cu128 torch 不匹配 → 手动装 `tensorrt-cu12==10.13.3.9`。
9. **停推流后前台全离线**：`feedLive` INNER JOIN `lp_room_state_snapshot`，该表靠 SRS 钩子维护；
   模式 B 必须补「从远端 SRS 同步状态」的定时任务。
10. **共享 CDN 的 CN 屏蔽**：若源机 CDN 回源有地区屏蔽，新机复用它会同样被屏蔽（国内 403），需海外访问或另配 CDN。

## 八、耗时参考（本次实测）

| 阶段 | 耗时 | 瓶颈 |
|---|---|---|
| 系统环境安装 | ~20 min | apt |
| 代码+素材+DB（~10G） | ~1 h | 跨境链路（家宽上行仅 ~0.25MB/s） |
| 模型 71G 两跳中转 | ~8 h | 每跳 ~5MB/s，串行 |
| ComfyUI + 节点 + 依赖 | ~40 min | pip 下载 |
| 端到端调通 | ~30 min | — |

> **结论**：真正的时间成本在**跨境传数据**。若新机能与源机同机房/内网，总时长可压缩到 1–2 小时。
