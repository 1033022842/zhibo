# 角色数据跨站同步（lp_home_character + 素材）

首页「推荐角色」来自**数据库**表 `lp_home_character`，素材存**对象存储**（同 bucket 不同项目前缀）。
`python .zcode/sync_clients.py` 只同步文件，既不改 DB、也不会复制对象存储里的角色素材，所以新角色上线后必须单独做一次数据同步。

适用：sugus 上新增/修改了角色，需要让 heygirl / kelymi / kiss 的首页推荐一致。

## 0. 站点与库对照

| 客户 | 主机 | 库 / 用户 | 对象存储项目前缀 |
|---|---|---|---|
| sugus（源） | 172.81.98.55 | `zhibo` / `zhibo` | `sugus` |
| heygirl | 172.81.99.11 | `live_platform` / `live` | `hey` |
| kelymi | 172.81.99.42 | `live_platform` / `root` | `kelymi` |
| kiss | 111.90.150.230 | `live_platform` / `live_platform` | `kiss` |

- PHP 根：`/www/wwwroot/douyin/php`；站点根：`/www/wwwroot/douyin/ai-girl-malaysia.com`
- 素材是**同一个 bucket**（`sugus-media`）+ 同一个 S3 网关（`.env [MEDIA] S3_ENDPOINT`），品牌之间只差 key 前缀 `pub|sec/<project>/…`（`php/app/common/library/media/Media.php:76 keyFor()`）。
- tier 规则：`chat_gifts/*` 走 `sec/`（签名访问），`home_character/*`、`covers/*` 等图片前缀走 `pub/`。
- 订单/用户/聊天记录等业务表**绝不要跨站复制**，只同步 `lp_home_character` 这类内容表。

## 1. 导出源站表

在 sugus 上：

```bash
mysqldump --no-create-info --complete-insert --skip-extended-insert --compact zhibo lp_home_character > /tmp/hc_dump.sql
```

## 2. 导入目标站（先备份）

把 `/tmp/hc_dump.sql` 传到目标站，套一层备份 + 清表 + 自增重置：

```bash
cat > /tmp/hc_import.sql <<'SQL'
CREATE TABLE IF NOT EXISTS lp_home_character_bak20261120 LIKE lp_home_character;
DELETE FROM lp_home_character_bak20261120;
INSERT INTO lp_home_character_bak20261120 SELECT * FROM lp_home_character;
DELETE FROM lp_home_character;
SQL

cat /tmp/hc_import.sql /tmp/hc_dump.sql > /tmp/hc_all.sql
printf 'ALTER TABLE lp_home_character AUTO_INCREMENT = <max_id+1>;\n' >> /tmp/hc_all.sql
mysql live_platform < /tmp/hc_all.sql          # 目标站库名
```

校验：`SELECT COUNT(*), MAX(id) FROM lp_home_character;` 应与源站一致；备份表行数 = 导入前行数。

## 3. 复制封面 / 预览图（本地读 → 目标前缀写）

在**源站**执行清单 + 上传（脚本随仓库走）：`.zcode/char_sync/media_sync.php`

```bash
# 清单：每行一个站内路径
mysql -N -B zhibo -e "SELECT cover_url FROM lp_home_character" | sed 's#^#/storage/#; s#^/storage//#/storage/#' > /tmp/paths_list.txt
for i in $(seq 1 135); do echo "/storage/chat_gifts/home-$i/preview_sd.mp4"; done >> /tmp/paths_list.txt

php /www/wwwroot/douyin/.zcode/char_sync/media_sync.php hey     /tmp/paths_list.txt
php /www/wwwroot/douyin/.zcode/char_sync/media_sync.php kelymi  /tmp/paths_list.txt
php /www/wwwroot/douyin/.zcode/char_sync/media_sync.php kiss    /tmp/paths_list.txt
```

输出 `pushed / nofile / failed`；`nofile` 表示源站本地本来就没有该文件（历史上老角色没有 preview_sd.mp4，属正常）。

## 4. 补齐礼物视频（bucket 内服务端复制，不占本机带宽）

新角色每个 `chat_gifts/home-N/` 有 13 个 mp4（rose、bouquet、preview_sd…）。
用 `.zcode/char_sync/media_copy.php`，它在源站直接发 `PUT` + `x-amz-copy-source` 让对象存储自己复制：

```bash
cd /www/wwwroot/douyin && cp .zcode/char_sync/media_copy.php /tmp/
nohup sh -c 'php /tmp/media_copy.php hey 88 135 > /tmp/copy_hey.log 2>&1; \
             php /tmp/media_copy.php kelymi 88 135 > /tmp/copy_kelymi.log 2>&1; \
             php /tmp/media_copy.php kiss 88 135 > /tmp/copy_kiss.log 2>&1; \
             echo DONE > /tmp/copy_all.done' >/dev/null 2>&1 &
```

清单模式（任意文件列表，如礼物图标）：`php media_copy.php <project> /tmp/icons_list.txt`，文件里每行写 `chat_gifts/icons2/rose.jpg` 这样的相对路径。

每项目 48×13≈624 个对象，约 10–15 分钟；日志里 `copied / failed / nofile`，`failed` 必须为 0。
进度查看：`ps aux | grep media_copy`（`pgrep -af "php media_copy"` 匹配不到带空格的参数）。

## 4b. 礼物目录（`lp_chat_gift` + `lp_chat_gift_role`）

新角色如果没有送礼入口，八成是这两张表没同步：

- `lp_chat_gift_role`：**每个角色一行**（`role_key` = `home-<id>`，`status=1`）。缺行 → `/api/live/chatGifts` 返回 `enabled=false` → 前端礼物按钮不出现，且礼物媒体不参与过滤。
- `lp_chat_gift`：礼物目录（`gift_key` 必须与 `chat_gifts/home-N/<gift_key>.mp4` 文件名一致）。各站目录可能不同（例如某些站是 `rose_single`/`necklace`），不同步会出现「同角色这边 9 个礼物、那边 11 个」。

```bash
# 源站导出
mysqldump --no-create-info --complete-insert --skip-extended-insert --compact zhibo lp_chat_gift_role > /tmp/gift_role.sql
mysqldump --no-create-info --complete-insert --skip-extended-insert --compact zhibo lp_chat_gift      > /tmp/chat_gift.sql

# 目标站导入（先备份到 _bak 表）
{ printf 'CREATE TABLE IF NOT EXISTS lp_chat_gift_role_bak%%s LIKE lp_chat_gift_role;'
  printf 'DELETE FROM lp_chat_gift_role_bak%%s;'
  printf 'INSERT INTO lp_chat_gift_role_bak%%s SELECT * FROM lp_chat_gift_role;'
  printf 'DELETE FROM lp_chat_gift_role;'; } | sed "s/%%s/$(date +%Y%m%d)/g" > /tmp/pre.sql
cat /tmp/pre.sql /tmp/gift_role.sql > /tmp/all.sql
echo "ALTER TABLE lp_chat_gift_role AUTO_INCREMENT=999;" >> /tmp/all.sql
mysql live_platform < /tmp/all.sql
```

礼物图标 `chat_gifts/icons2/*.jpg` 也要按品牌前缀复制（走 `sec/`），否则礼物面板图标 404。

## 5. 验证

```bash
# 首页前 12 个角色应四站一致
for d in sugus.ai heygirl.live kelymi.autos kisss.ai; do
  curl -s "https://$d/api/v1/home/characters?limit=12" | head -c 300; echo; done

# 礼物目录应四站一致（enabled=true，条数相同，图标 200）
for d in sugus.ai heygirl.live kelymi.autos kisss.ai; do
  curl -s "https://$d/api/live/chatGifts?role_key=home-135" | head -c 200; echo; done
```


最后跑一遍静态站硬验证：`python .zcode/verify_client.py --client all`。

## 6. 回滚

- DB：目标站 `lp_home_character_bak<日期>` 表，`DELETE FROM lp_home_character; INSERT INTO lp_home_character SELECT * FROM lp_home_character_bak<日期>;`
- 对象存储：多出来的 `sec|pub/<project>/chat_gifts/home-<新id>/` 前缀可直接删（只影响新角色）。
