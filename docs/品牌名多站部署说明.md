# 品牌名在多站部署中的处理（登录弹窗左侧图）

> 记录 2026-11-09 修复「登录弹窗左侧图片底部品牌名」时的多站适配方案。
> 以后改任何**带品牌名文案**的页面，先读这份。

## 一、核心机制：业务文件保持中性，品牌在部署期改写

四站（sugus / heygirl / kelymi / kiss）共用一个上游仓库 `douyin`。
**业务文件里只写 Sugus 的品牌词**，部署时由各站 `/opt/brand-kit/tools/apply_brand.sh`
按 `sed` 规则替换成本站品牌。所以：

- ✅ 上游业务文件里写 `Sugus.ai` 是**正确做法**，不要写「本站品牌名」之类抽象占位
- ❌ 不要在上游业务文件里写 heygirl / kelymi / kiss 的品牌名
- ❌ 不要用图片/SVG 承载品牌名（见第三节）

各站替换规则（`apply_brand.sh`）：

| 站 | 规则 | 登录弹窗最终显示 |
|---|---|---|
| sugus | 不跑 apply_brand（它就是上游） | `Sugus.ai` |
| heygirl | `s/Sugus\.ai/heygirl.live/g` | `heygirl.live` |
| kelymi | `s/Sugus\.ai/Kelymi/g` | `Kelymi` |
| kiss | `s/Sugus\.ai/Kisss/g` | `Kisss` |

## 二、正确写法（当前实现）

```html
<div class="absolute bottom-0 w-full mb-8 flex justify-center items-center">
  <span style="font-family:Poppins,-apple-system,'Segoe UI',sans-serif;
               font-size:26px;font-weight:800;letter-spacing:-0.3px;color:#fff;
               text-shadow:0 2px 14px rgba(0,0,0,.75),0 0 3px rgba(0,0,0,.5);
               pointer-events:none">Sugus.ai</span>
</div>
```

要点：
- 用 `<span>` **纯文本**，品牌名是**独立文本节点**，`sed 's/Sugus\.ai/.../g'` 能命中
- 不要拆成 `<span>Sugus</span><em>.ai</em>`（部分站点规则只匹配 `Sugus<em>.ai</em>` 这一种组合，
  拆错会漏替换）
- 父级 `#user-login-image` 有 `position:relative`，`absolute bottom-0` 才能贴图片底部
- `pointer-events:none` 避免挡住下层点击

## 三、为什么不能再用 SVG 图（重要教训）

原实现用的是 `*_files/sugus.ai-<hash>.svg`。踩了两个坑：

1. **内容与文件名不符**：那个 SVG 里画的其实是 **candy.ai**（从参考站抓来的素材，
   文件名被错标成 sugus.ai）。上线后用户看到的是别家品牌。
   → 排查方法：`grep -c 'candy' ` 或直接打开 SVG 看 `<path>` 数据，别信文件名。
2. **`apply_brand.sh` 改不了它**：品牌在 SVG 路径数据里，`sed` 处理的是文本。
   脚本对 SVG 只做「按文件名 `sugus.ai-*.svg` 整份替换成客户词标」，
   这要求客户 brand kit 里**确实存在** `assets/wordmark.svg`。缺这个文件时品牌就停在 sugus。

所以品牌名一律用**文本**，跨站零维护成本。

## 四、必须同步改的覆盖文件（最容易漏）

`sugus` 和 `heygirl` 的 `Image.html` 走 `client_overrides/`，**会覆盖上游同名文件**。
改上游 `ai-girl-malaysia.com/Image.html` 对它们无效。

本次新增/涉及时两个都要改：

```
client_overrides/image-sugus/Image.html
client_overrides/image-heygirl/Image.html
```

SOP 要求这两份**除脚本版本号与 MEDIA_CDN 外内容一致**。校验：

```bash
diff <(sed -E 's/(shell-new\.js\?v=|creator-guide\.js\?v=)[a-zA-Z0-9]+/\1XXX/g' client_overrides/image-sugus/Image.html) \
     <(sed -E 's/(shell-new\.js\?v=|creator-guide\.js\?v=)[a-zA-Z0-9]+/\1XXX/g' client_overrides/image-heygirl/Image.html)
```

预期差异只有：`MEDIA_CDN`（sugus→media.sugus.ai / heygirl→media.heygirl.live）、
`customVideo.js?v=`、个别 class。

## 五、部署后验收（必做）

```bash
# sugus（直连 98.55）
curl -s -H 'Host: www.sugus.ai' http://127.0.0.1/ai/Girls.html | grep -o 'pointer-events:none">[^<]*</span>'
# → Sugus.ai

# heygirl / kelymi 走 8081 回源口，不是 80
curl -s http://127.0.0.1:8081/ai/Girls.html | grep -o 'pointer-events:none">[^<]*</span>'
# → heygirl.live / Kelymi
```

⚠️ **heygirl 和 kelymi 的 80 端口是 `zhibo.conf`，静态页 404 是正常的**；
静态站要打 `:8081`（Bunny 回源口，`/ai/` alias 到 `ai-girl-malaysia.com/`）。

## 六、新增站点 checklist

1. 在 `sync_clients.py` 的 `CLIENTS` 里配 `brand` / `brand_kit` / `verify_expect`
2. `/opt/brand-kit/brand/<客户>/` 放好 logo/wordmark/favicon/share_card
3. `apply_brand.sh` 里确认有 `s/Sugus\.ai/<新品牌>/g` 这条规则
4. 部署后按第五节验收，确认登录弹窗显示的是本站品牌
