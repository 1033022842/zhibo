## 三、关键路径

| 路径 | 内容 |
|---|---|
| /opt/channel-worker/worker.py | 推流主程序（copy 推流改造版，与仓库 services/channel-worker/python/worker.py 同步） |
| /data/media/{人设}/ | 原片素材（含 礼物/、特写/ 子目录） |
| /data/runtime/ts_cache/ | 720p 预转 TS 缓存（相对路径哈希，跨机通用） |
| /data/hls/room/{id}/ | SRS 输出 HLS（nginx root=/data/hls 对外，`/hls/` 前缀已做 ^~ 重写） |
| /data/srs/srs.conf | SRS 配置（on_publish 钩子 → 164 php） |
| /etc/systemd/system/live-worker@.service | worker 模板服务（DB/Redis 指 164，PUSH_COPY=1，720:1280@30 cq24） |
| /opt/mediamtx/ | MediaMTX（WebRTC/WHEP 中继）：从 SRS 按需拉 rtmp://127.0.0.1:1935/room/{id}，WHEP 端口 8889 / ICE UDP 8189 |

## 三B、观众播放链路（2026-09-12 定稿）

```

前端 hls_url   → https://ever-candy.b-cdn.net/hls/room/{id}/index.m3u8（Bunny 回源 http://172.81.98.55）
```

- 164 php/.env `[AI]` 段：`HLS_CDN_DOMAIN = https://ever-candy.b-cdn.net`（RoomService.hlsBase 已兼容 AI 段读取）
- 改动过 164：RoomService.php hlsBase()、Whep.php mediamtxUrl → 172

## 四、换素材 / 加房间流程

1. 新素材按 `{人设}/{视频}.mp4`（礼物放 `礼物/`、特写放 `特写/`）放入 /data/media/
2. 720p 预转：有 N 卡的机器用 NVENC（如 AI 电脑 D:\ever\worker_v2 + pretranscode_v2.py 模式），
   172 本地也可直接跑（worker 启动时自动预转，libx264 16核很快）
3. DB 入库参照 D:\ever\ai_web_assets\import_v2.py（幂等脚本：asset→playlist→room→binding→礼物）
4. `systemctl restart live-worker@{id}` 生效

## 五、注意事项

1. **流名必须是 `room/{数字}`**：SRS on_publish 钩子只认数字房间号，别的流名会被拒
2. **Redis 礼物消息格式**：`{"params":{"keyword":"傲娇"}}`（lpop list:keyword:room:{id}）
3. copy 推流模式下**码率由预转参数决定**（当前 720p cq24 ≈1.3Mbps；白毛女源码率高 ≈6-8Mbps）
4. 172 无 GPU：worker 已做 NVENC 实测探测（TS_NO_NVENC=1 亦可强制 libx264）
5. SRS 是 Docker（--network host），配置改动后：`docker rm -f srs && docker run -d --name srs --restart always --network host -v /data/srs/srs.conf:/usr/local/srs/conf/srs.conf -v /data/hls:/data/hls ossrs/srs:5 ./objs/srs -c conf/srs.conf`，再 restart 各 worker
6. AI 电脑旧推流任务（AIWorkerRoom1）已不再需要，保留未删（手动触发型，不会自启）
