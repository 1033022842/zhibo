# PHP 漂移分析结论（2026-11-14）

> 背景：`sync_clients.py` 的 `tree_hashes()` 只扫站点目录，`php/` 从来没进过变更集，
> 因此 `in_scope()` 里的 PHP 同步分支是死代码。要在修掉它之前，先摸清四站 PHP 与仓库
> 的真实差异，否则一放开就是四站同时被覆盖。
>
> 采集方式：`.zcode/_phpdrift_capture.py`（只读，把远端文件抓到 `D:\ever\douyin\_phpdrift\`）
> 分类方式：`.zcode/_phpdrift_classify.py` + `_phpdrift_report.py`
> 原始报告：`D:\ever\douyin\_phpdrift\_classify.json`

## 一、总量

| 站点 | differs | remote_only | repo_only |
|---|---|---|---|
| heygirl | 31 | 2 | 59 |
| sugus   | 28 | 2 | 57 |
| kelymi  | 29 | 1 | 58 |
| kiss    | 52 | 2 | 79 |

- `remote_only`：服务器有、仓库没有 —— 全部是临时探测脚本或运行时产物
  （`public/_bnbprobe.php`、`public/storage/shorts/manifest.json`），**不入库**。
- `repo_only`：仓库有、服务器没有 —— 绝大多数是**不该部署的**东西：
  `database/migrations/`、`sql/upgrade_*.sql`、`_test_*.php`、`check_model.php`、
  `composer.json`、`web/package.json` 等。这些**不是漂移**，是 in_scope 判得太宽。

## 二、真正需要关注的 differs（按性质分四类）

### A 类 · 空白/换行差异（14~15 个 / 站）

四个站都有同一批。典型是 PHP 数组对齐被编辑器重排：

```diff
-                        'chat_overage_price'   => '1',
+                        'chat_overage_price'    => '1',
```

**处理**：忽略。仓库版本覆盖回去无任何行为变化。

### B 类 · 品牌替换（1 个）

`php/sql/upgrade_register_email_verify.sql`：线上是客户站点改过的注释与 remark 文案。
**处理**：忽略（SQL 迁移脚本本来也不部署）。

### C 类 · 仓库更新（多数）

服务器上是旧版，仓库里是后来的迭代。特征：仓库独有标识符远多于线上独有。
例如：

| 文件 | 仓库独有 |
|---|---|
| `app/live/service/PromoService.php` | `NO_PIXEL_PLATFORMS`、`PLATFORM_SHORT` 等 92 个 |
| `app/ai/service/AiTaskService.php` | `ai_short_video` / `GenCreditService` 等 68 个 |
| `app/api/route/recharge.php` | `HissPay` / `Cregis` / `WisonPay` 等 23 个 |
| `app/live/service/InviteService.php` | 佣金统计相关 35 个 |

**处理**：仓库覆盖即可 —— 但**必须逐站确认该站没有自己的定制**（见 D 类）。

### D 类 · 线上独有改动（关键风险，共 3 处）

#### D1. `kiss` — `app/live/service/UserService.php`

```diff
-            if (AgentService::ready()) {
+            // 代理归因：本站未接入代理体系时该服务类不存在，跳过（避免注册/社交登录 500）
+            if (class_exists(AgentService::class) && AgentService::ready()) {
```

已核实：**kiss 服务器上不存在 `AgentService.php`**（`test -f` 为 NO，全站仅 1 处引用）。
这是 kiss 独有的运行时兜底，仓库里没有。

⚠️ 若按仓库版本覆盖，kiss 的**注册与社交登录会直接 500**。

#### D2. `kiss` — `app/admin/controller/live/PromoSetting.php`

线上是**旧版**（无 `NO_PIXEL_PLATFORMS`、`buildPromoLink` 只有 3 参），
且线上独有 `$linkName` 变量与 4 参调用 —— 说明 kiss 曾经手改过，后又落后于仓库。
需要合并：以仓库新版为基，确认 `$linkName` 那套逻辑是否已被仓库的 `NO_PIXEL_PLATFORMS` 方案取代。

#### D3. `kelymi` — `php/config/starpay.php`

```diff
-    'merchant_no'    => (string) env('starpay.merchant_no', ''),
-    'key'            => (string) env('starpay.key', ''),
+    'merchant_no'    => 'TS-PLACEHOLDER-MERCHANT-NO',
+    'key'            => 'PLACEHOLDER-KEY-REPLACE-BEFORE-GO-LIVE',
```

线上是**占位符**（说明 kelymi 未接 StarPay，但有人把 env 读取改成了硬编码占位）。
**处理**：仓库版本更正确（走 env），覆盖反而更好。但需确认 kelymi 是否真的不用 StarPay。

### 其余「线上独有」但无需处理的

| 文件 | 原因 |
|---|---|
| `config/media.php` / `config/buildadmin.php` / `config/console.php` | 0 个独有标识符，纯格式 |
| `config/skytrade.php` | 各站商品清单不同（sugus 是服装、heygirl 是饰品），**属正常客户差异** |
| `command/FiatRateCron.php` | 0 个独有标识符 |
| `sql/upgrade_skytrade.sql` | 商品名 `stripe`→`Credit Card`，SQL 不部署 |
| `app/live/service/EmailVerifyService.php`（sugus） | 方法顺序不同，语句集合等价 |
| `app/live/controller/UserController.php`（sugus） | 仅 `use` 顺序不同，语句集合等价 |

## 三、结论与建议

1. **不要**直接把 `tree_hashes()` 放成整目录 —— 会同时覆盖四站，D1 会立刻让 kiss 注册挂掉。
2. `in_scope_php()` 应排除「不该部署」的目录：`database/migrations/`、`sql/`、`web/`、
   `tools/`、`_test_*.php`、`check_model.php`、`test_*.php`、`composer.json`。
3. 修 `tree_hashes()` 应分站灰度：先 heygirl（漂移最少、定制最少），再 sugus，
   最后 kelymi / kiss（把 D1/D2/D3 先合进仓库）。
4. D1 必须先进仓库，否则 kiss 永远不能吃 PHP 同步。
