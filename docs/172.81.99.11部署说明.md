## 三、已跑通的业务

### 直播（本机推流，10 路在线）
- `live-worker@{1,17,18,19,20,22,23,24,25,26}` → 推 `rtmp://127.0.0.1:1935/live/room/{id}`
- SRS（docker 容器 `srs`）→ HLS 落盘 `/data/hls/room/{id}/`
- nginx `/hls/` 别名 `/data/hls`，玩家直接拉源站 HLS（**未走 CDN**）
- SRS 的 `on_publish/on_unpublish` 钩子 → 回调 `http://127.0.0.1/api/v1/srs/{publish,unpublish}` → 维护 `lp_room_state_snapshot.current_state`
- 已验证闭环：停 worker → 快照 `offline` → 移出 feed；启 worker → `public_live` → 进 feed

### ⚠️ 内部回调（关键，勿删）
`nginx` 里必须有一个 **`listen 127.0.0.1:80`** 的 server。原因：
- SRS 回调钩子写的是 `http://127.0.0.1/api/v1/srs/*`
- worker 上报写的是 `http://127.0.0.1/api`
- 一旦把 80 只绑到具体公网 IP（`.11/.29/.49`），`127.0.0.1:80` 就没人监听 → 钩子 `Connection refused` → **推流被拒、HLS 全空**。
- 已在配置里保留该内部 server；排查时 `curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1/api/v1/feed/live?limit=1` 应返回 200。

### 数据
- 库 `live_platform`（`ba_` 框架表 + `lp_` 业务表），26.2 MB，14 房间 / 1262 素材 / 25 用户
- 素材 `/data/media/{人设}/`（含 `礼物/` `特写/`），2.4G
- 转码运行态 `/data/runtime/`，2.2G
- 上传资源 `/www/wwwroot/douyin/php/public/storage/`，18G

### WebSocket
- `zhibo-ws`（webman）HTTP `:8787` / WS `:8788`，systemd 常驻

多域名证书签发**要求整组域名的 80 端口都必须能通过校验**，只要有一个域名没解析/80 不通，整张证书就会失败。所以务必先确认 7 条解析全部就绪再跑。

脚本做 6 件事：DNS 校验 → 部署 HTTP 配置 → `certbot` 签两张证书（主域一张、后台一张）→ 部署 HTTPS（80 跳 443）→ 改 `php/.env`（HLS 域名 + 支付回调/回跳）与 `buildadmin` CORS → 验证。

### 为什么大部分不用改代码

- 后端 URL（播放、图片、回调）多走 `request->domain()` **动态生成**，自动跟随访问域名。
- SPA/静态站前端一律用**相对路径** `/api/...`，WebSocket 用 `window.location.host`。
- 推广域名在前端每次请求 `/api/v1/site/config` 时会被**自动收录**进 `promo_site_domains`（见 `PromoService::rememberDomain`），无需手填。
- 所以只需：nginx `server_name` + `php/.env` 的 `AI.HLS_CDN_DOMAIN` + 支付回跳 + CORS 白名单。

### 域名上线时必须注意

1. **HTTPS 要成套**：页面走 https 后，HLS 也必须 https（否则被浏览器按混合内容拦截）。脚本把 `heygirl.live` 与 HLS 放同一张证书。
2. **支付配置是写死的**：`[STARPAY] / [FLOWPAY]` 的 `MERCHANT_NO / MCHID / KEY` **仍需换成新客户自己的商户**，脚本只改了 `NOTIFY_URL / RETURN_URL*`（自动指向主域），商户号/密钥不能沿用原客户的。
3. `vue/src/pages/login/Login.vue` 里原先把注册跳转写死成 `:8082`，已改为 `/ai/Login.html`，**并已在服务器重新 `npm run build` 生效**（2026-10-09），旧 dist 备份在 `vue/dist.bak`。
4. certbot 会自动续期（`systemctl status certbot.timer`）。
5. Cloudflare 用户必须关掉橙云（DNS only），否则隐藏真实 IP、三 IP 分工失效。

## 八、Bunny CDN 接入（2026-10-09 已上线）

直播 HLS 现在走 Bunny CDN，源站是 `.49`，观众拉流不再直连源站。

### 配置参数

| 项 | 值 |
|---|---|
| CDN 域名 | `hey-girl.b-cdn.net` |
| **Origin URL** | **`http://172.81.99.49`**（★ 只填到 IP，**不要带 `/hls` 路径**） |
| Origin Host Header | 留空（源站 `server_name _` 兜底） |
| 缓存 | 遵循源站 Cache-Control（源站已给对：m3u8 不缓存 / ts 缓存 1 天） |
| Custom Hostname | **不需要**（直接用 `b-cdn.net`） |
| 应用侧 | `php/.env` 的 `[AI] HLS_CDN_DOMAIN = https://hey-girl.b-cdn.net` |

> ★ **Origin URL 不能带路径**：Bunny 回源规则是 `Origin URL` + 请求路径拼接。播放地址本身已带 `/hls/`，若 Origin 再填 `/hls` 会变成 `/hls/hls/...` 双重路径而 404。
> 回源走 HTTP 是正常的（`.49` 是纯 IP 签不了证书）；用户看到的始终是 `b-cdn.net`，源站 IP 不暴露。

### 验证方法

`.../index.m3u8` 是文本清单，**浏览器无法直接播放/显示**（打开空白或下载文件属正常），要用播放器或命令行验证：

```bash
# 取 m3u8（应返回 #EXTM3U 文本）
curl -s "https://hey-girl.b-cdn.net/hls/room/17/index.m3u8?v=2" | head
# 取最新片段（应 200 video/mp2t）
ts=$(curl -s "https://hey-girl.b-cdn.net/hls/room/17/index.m3u8?v=2" | grep -oE '^[0-9]+\.ts' | tail -1)
curl -sI "https://hey-girl.b-cdn.net/hls/room/17/$ts" | grep -iE 'HTTP/|content-type|cdn-cache'
```

### 运维注意

- **`.49` 的 HLS server 块必须保留**（即使不接 CDN）。曾因绑定脚本在无 `--hls` 时删掉该块，导致 CDN 无源可回；脚本已修，现始终保留。
- 手动测旧片段可能 404 —— 直播切片窗口仅 ~28 秒，旧片段轮转即删，属正常；播放器只取最新片段。
- 换 CDN 时：改 `php/.env` 的 `HLS_CDN_DOMAIN` → `systemctl restart php8.3-fpm`；CDN 侧改 Origin URL。
